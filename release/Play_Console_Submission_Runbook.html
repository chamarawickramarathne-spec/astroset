6 Release Track & Upload

  1. Play Console menu: Release > Production → Create new release.
  2. (Recommended first) Instead test privately first through Release > Testing > Internal testing → Create new release. This lets you install via opt-in link before public launch.
  3. Upload the AAB: drag release/AstroSet-android.aab into the App bundle drop zone.
  4. Wait for the bundle to be processed; Play validates signing, format, and SDK levels.
  5. Upload deobfuscation file: release/AstroSet-android-mapping.txt — attach it next to the AAB (it un-hides R8-obfuscated stack traces in ANRs/crash reports).
  6. Release name (optional): e.g. 1.3.1.
  7. Rollout: internal testing → 100% of testers (you). Production rollout can be 0% staged or 100%.
Do NOT upload these: the Mod 035-era artifacts. Current build is versionCode 8 / versionName 1.3.1. Play rejects an upload with a lower versionCode than one already on the track.
Sign-in review: AstroSet has no sign-in. The "Sign-in with Google" section should auto-be marked as No, no action needed.

7 Review & Publish

  1. Click View release summary and double-check country coverage, release notes, and bundle.
  2. Add release notes (optional but recommended):
    New: Vedic/Western astrology, planetary alignment chart, moon events, live solar flares & space weather, Schumann Resonance monitor, 7-day weather with UV index. Completely free with no ads.
  3. When an internal-testing release is reviewed, you'll get an opt-in link like https://play.google.com/apps/testing/com.vortex.astro — open it on your phone, install, and verify the app launches and loads data.
  4. Once verified, Promote to production or create a production release and Roll out the release.
  5. Post-publish review typically takes a few hours to a few days. You can use the limited "test" release while reviewing.

8 After Publishing — Updating the App

JavaScript-only changes (no Play Store visit needed)

Set EXPO_TOKEN (in credentials.txt), then from project root: eas update --channel default --environment production --message "what changed" --non-interactive

Installed apps fetch the new JS bundle automatically on launch (OTA via EAS Update).

Native changes (requires a new Play release)

  1. Bump versionCode and optionally versionName in app.json and android/app/build.gradle.
  2. Rebuild: .\android\gradlew.bat :app:assembleRelease :app:bundleRelease (from project root).
  3. Copy new files to release/:
Copy-Item .\android\app\build\outputs\apk\release\app-release.apk .\release\AstroSet-android.apk -Force Copy-Item .\android\app\build\outputs\bundle\release\app-release.aab .\release\AstroSet-android.aab -Force Copy-Item .\android\app\build\outputs\mapping\release\mapping.txt .\release\AstroSet-android-mapping.txt -Force
  • Upload the new AAB + mapping.txt to the Play track (must have higher versionCode).

    • Fast Q&A — Common Form Questions

    Does the app collect personal data?

    No. Settings (location, zodiac, notification prefs) and cached data live only on the device in AsyncStorage. There is no backend server.

    Does it have ads?

    No ads. AdMob/Google Ads SDK was fully removed (Mod 034). The APK verification confirms zero com.google.android.gms.ads classes and no AdMob IDs.

    What permissions does it use?

    POST_NOTIFICATIONS (optional daily notifications), RECEIVE_BOOT_COMPLETED (restore scheduled notifications after reboot), and internet access for live data. No location services, no camera, no contacts, no microphone.

    Which privacy policy URL goes in the store?

    https://chamarawickramarathne-spec.github.io/astroset/privacy.html

    Why versionName "1.3.1" and not "1.3.1.0"?

    Play rejects version names with a trailing .0. Keep the current format; PSB already handles this.

    What if Play asks for a privacy policy on the data safety page?

    Paste the same GitHub Pages URL above. It's ad-free and hosted on the public repo.
